# Decisions log

- **Docs IA color unification:** The shared semantic root palette now uses the already established Home values so Docs, navbar, Components, Playground, Showcase, shared controls, and Home share the same page, text, border, and accent colors. This changes the palette for all consumers of those global tokens; Home's existing values were not changed. Copy confirmation uses the existing brand violet instead of standalone green literals. The contrast audit records pre-existing low-contrast hairline borders; the checker does not treat those as new failures.
- **Docs heading typography:** The shared PageHeader is used by the Docs, Components, and Playground routes, so it now uses the existing Home sans-serif title scale consistently across those pages. Docs section headings use the Home h2 scale and 48px spacing. Home hero typography is unchanged.
- **Components gallery visibility:** Include `@rivinia/menu` because its installed manifest exposes a public `./ui` entry point and the package provides menu behavior. Exclude `@rivinia/popup` because it exposes no `./ui` entry point and its verified description identifies shared popup mechanics rather than a user-facing component.
- **Phase 2 Step 2 — Select displayed source:** The Select component imported the showcase highlighter and source model. Moved the code-block definitions and highlighting into `select-example.registry.ts`, loaded by the lazy showcase loader, and passed the result to the component as an input. This keeps the visitor-facing component free of application-local imports while preserving its rendered examples.
- **Phase 2 Step 6 — manifest translation key:** A package can have different existing text keys on the components page and in the showcase. Kept the single manifest `translationKey` as the components-page summary when that visibility exists; showcase-only entries use their existing showcase name key. The showcase keeps its existing ID-based display-name lookup to preserve labels for packages visible in both places.
- **Home redesign — version badge:** Omit a global package-version badge because the root application package version is `0.0.0`, not a verified library release version. Show package-specific metadata only after rechecking it.
- **Home redesign — integration:** Preserve real lazy demos, existing app architecture, i18n, RTL, and preference controls.
- **Home redesign — documentation routes:** The repository has general `/docs` and `/components` routes, but no per-package documentation route. Link to the general docs/catalog and do not imply a package-specific docs page.
- **Decisions section — performance claim:** Replaced “Fast by default” with “Signal-based state”; the repository exposes signal-backed state, but no performance benchmark supports a speed claim.
- **Decisions section — accessibility wording:** Describe the verified boundary: the ready UI documents keyboard/ARIA behavior, while headless leaves semantics and focus to consumer markup.
- **Docs surfaces — one folder per surface:** Each Docs surface (`shell`, `hub`, `getting-started`, `library-overview`, `package-filter`, `not-found`, `shared`) owns its components, models, and services. Characterization specs were written before the moves, and every step kept the existing DOM, ids, ARIA, and visuals unchanged. Shell and hub keep separate package-search instances so the sidebar never matches descriptions while the hub does, and surface services use `@Service({ autoProvided: false })` with component-level providers so state cannot leak between surfaces. The quick-start source loader is an injection token so the stale-response guard can be tested without the real showcase loader.
- **Docs package sidebar panels:** A package page switches the Docs sidebar from its grouped package index to a panel of that page's rendered headings. Back returns to the index without changing the route and restores focus to the package link. Use one full-panel translate per level (500ms smooth-out), reverse it for RTL, honor reduced motion, and keep the existing whole-sidebar collapse independent.
