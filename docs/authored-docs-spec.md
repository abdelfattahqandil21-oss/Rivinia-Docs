=== E2. THE EXAMPLE ENGINE (this is what makes the site more than ordinary docs) ===

- An example is a folder src/content/docs/<pkg>/examples/<name>/ with `meta.json` { title, scenario (2 sentences, who needs this), tryIt: [2-4 short things to do in the preview], mode: "component" | "frame", minHeight, variants: ["theme", "dir"] subset } plus its files. mode "component": an entry file `<name>.example.ts` (standalone Angular component, inline template/styles; extra files such as a service allowed in the folder). mode "frame": an `index.html` (with inline CSS/JS) that is the shown code AND the preview.
- scripts/generate-docs-examples.mjs writes src/generated/docs-examples.generated.ts: name -> { meta, files: [{ path, source }], load }. For frame examples it builds `srcdoc` at generation time, inlining any package CSS it references (for example @rivinia/theme styles/theme.css) from node_modules; no external requests.
- <app-docs-example> block: title and scenario, a controls row (only the declared variants: Theme Light|Dark applied to the preview container, Direction LTR|RTL, Reset), a Preview/Code switcher with text labels (side by side at >= 1100px), file tabs for multi-file examples with <app-copy-button> per file, and a "Try this" list under the preview. Preview loads with @defer (on viewport; prefetch on idle) in a reserved min-height box (no layout shift). Frame examples use `<iframe sandbox="allow-scripts" title="...">`, no same-origin. An example must NEVER change the docs site's own root tokens, attributes, or storage: component examples render inside a scoped container, root-level behavior (such as an attribute on <html>) is shown only in frame mode.
- Examples are real files: include them in tsconfig.app.json and tsconfig.spec.json so they compile in `npm run verify`; a deliberate type error must make verify fail (prove it once, then revert). Allowed imports in component examples: @angular/_, @rivinia/_, and files inside the same example folder. Forbidden: imports from src/app, i18n pipes, icon libraries, ::ng-deep, !important. Every service or logic file has a spec next to it.
- check:docs-content also verifies: every `:::example` name exists; every `ts` code fence that imports from '@rivinia/*' names real exports of the installed package entry point (port reference/audit-docs-imports.mjs from the zip); internal links resolve; heading ids are unique per page; no color literals in app UI (examples and content are exempt).
